# Презентация KODES

Анимации доклада: manim CE рисует сцены, `manim-slides` собирает их в `.pptx`,
где каждый слайд — видео, запускающееся по щелчку.

## Что где

| файл | что внутри |
| --- | --- |
| `presentation.py` | все сцены; границы слайдов — вызовы `self.next_slide()` |
| `theme.py` | палитра, шрифт, сетка, кристаллы, полосы памяти |
| `manim.cfg` | фон, разрешение, частота кадров |
| `render.sh` | рендер + сборка `kodes.pptx` |

Все сцены обязаны лежать в одном файле: manim ищет их только в том модуле,
который ему передали, импортированные классы он не видит.

## Установка

Системные пакеты (колёс под Linux у `manimpango` и `pycairo` нет, они собираются
из исходников; `ffmpeg` нужен manim, LaTeX — формулам):

```sh
sudo apt install -y build-essential python3-dev pkg-config \
    libcairo2-dev libpango1.0-dev ffmpeg \
    texlive texlive-latex-extra texlive-fonts-extra texlive-science dvisvgm cm-super
```

Python-часть — в локальный `venv/` рядом с этим файлом:

```sh
python3 -m venv venv
./venv/bin/pip install manim "manim-slides[pptx]"
```

## Рендер

```sh
./render.sh            # 1080p30, затем kodes.pptx
./render.sh -l         # черновое качество (480p15), для проверки правок
./render.sh S09Warp    # одна сцена
```

Частоту кадров задаёт флаг качества, а не `frame_rate` из `manim.cfg`: `-qh` сам
по себе даёт 1080p60 — вдвое дольше и вдвое тяжелее при той же картинке на
экране, поэтому в `render.sh` стоит явный `--fps 30`. Полный рендер — около часа.

Готовые видео — в `media/videos/presentation/1080p30/`, сборка — `kodes.pptx`.
Открывается в PowerPoint и в LibreOffice Impress; на чужой машине надёжнее
показывать `manim-slides present`, а `.pptx` держать как запасной вариант.

## Порядок сцен

1. `S01Title` — заглавие.
2. `S02Splitting` — операторное расщепление: почему химию считают отдельно.
3. `S03Independence` — в шаге химии ячейки ничем не обмениваются.
4. `S04CPU` — очередь ячеек через CPU.
5. `S05GPUIdea` — параллелить по системам, а не внутри системы.
6. `S06NaiveTransfer` — версия 1: перенести всё разом, упереться в VRAM.
7. `S07Batches` — версия 2: батчи; рабочая память простаивает.
8. `S08Chunks` — версия 3: рабочая память по числу резидентных потоков.
9. `S09Warp` — варп идёт со скоростью самой жёсткой ячейки.
10. `S10Balancer` — версия 4: блочная сортировка батча по ключу.
11. `S11Summary` — итог.

## Числа, на которые опираются слайды 6–8

GRI-Mech 3.0, 53 вида, `double`, VRAM 8 ГБ, ансамбль 10⁶ ячеек:

| величина | оценка |
| --- | --- |
| состояние одной системы | `53 · 8 Б` ≈ 0.43 КБ |
| рабочие массивы одной системы | `2 · 53² · 8 Б` + временные ≈ 45 КБ |
| версия 1: рабочая память на весь ансамбль | ≈ 45 ГБ — не влезает |
| версия 2: батч по VRAM | ≈ 176 000 систем, ≈ 6 передач; полезны 8 192 слота из них |
| версия 3: рабочая память | `8192 · 45 КБ` ≈ 0.37 ГБ, на состояния остаётся ≈ 7.6 ГБ |

Числа — порядковые оценки для доклада; точные размеры считает `planLaunch`
по занятости ядра на конкретном устройстве.
